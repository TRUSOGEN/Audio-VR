## A. 技术实现与检查（先完成）

1. 为每个独立片段建立唯一 excerpt/event ID，目标由独立私有随机流抽取，种子与实际目标落盘；参与者知晓目标可重复，不展示答案、分配表或“每类恰好一次”的规则。
2. 通知之前至识别截止使用对目标不可辨的前置画面与运动。逐帧检查 HUD、地图进度、窗外高度/地标、机舱运动、片段标题、等待时长和重置行为；目标不能提前影响视觉任务 RNG 或输入反馈。若无法兼顾场景可信度与目标不可辨性，记录失败并调整允许结论。
3. 定义固定通知起点 t0、识别窗 W、信心窗 C 和阶段变化间隔 L；要求 L > W+C 并留处理余量。当前数值全部 provisional。阶段变化由固定时钟调度，不随答案时刻或正确性触发。用快答、晚答、错误、timeout、暂停/中断逐类检查真实日志。
4. 建立专用 visual-only 验证模式：保留与候选一致的视觉、控制和背景噪声情境，抑制通知内容及其他阶段声音；用所有目标一致的中性提示确定预测时点。中性提示只能启动回答，不能编码目标。该模式不加入正式 2×2 比较，不写成研究的第五条件。
5. 保存版本化录屏及日志，盲化材料不要包含文件名中的目标代码、调试文字或片段结尾的答案。审查者在预测提交前不能接触目标表。若重复观看或呈现结尾会教会策略，必须记录曝光历史，使用新的保留片段检查。
6. 对正式候选配置检查相同音量路径、输入、时钟、日志和呈现；“软件无通知请求”不能替代实际输出路径的静音检查。当前英文 UI 截图只作工程记录和布局说明。

完成判据：目标与非音频输出的依赖检查无可直接解码规则，时序/缺失/中断日志完整，候选片段真实可运行。技术通过仅允许进入 B，不构成人类效度证据。

## B. 盲化视觉线索检查（依赖 A 与伦理覆盖）

招募不知道分配表的测试者，按统一训练和三选一标签，仅依赖可见信息预测下一目标。收集首次回答、无回答、理由及使用的信息；不提示“应该接近随机”。尽量避免执行者无意透露目标，用预生成材料和标准脚本。

在开始前填写并保存以下决定；空白时不得判定通过：

| 决定 | 当前状态 |
| --- | --- |
| 独立测试者人数、每人事件数与保留片段 | 待按希望排除的线索优势和可行性论证 |
| 可容忍的超基线预测优势与置信界限规则 | 待预设；不能事后按结果选阈值 |
| 分配规则、提示、历史曝光条件及猜测基线 | 待候选实现冻结；三等概率独立标签的 1/3 仅是参考 |
| 技术无效、无回答、退出和缺失处理 | 待预设；技术无效单列，不选择性删除错误 |
| 伦理/同意、录屏/录音及匿名存储 | 依现有项目批准范围核对 |

记录字段：`review_protocol_version, build_hash, reviewer_id, excerpt_id, event_id, actual_condition, target, target_schedule_hash, prior_exposure, prompt_onset_ms, prediction_ms, predicted_target, no_response, stated_reason, suspected_cue, technical_invalid_reason, recording_ref`。答案键与盲化材料分开保存，仅在预测锁定后联结；不存在人类数据时保持空表，不填示例成绩。

同时报告随机选择参考、预先指定的序号/历史/情境策略基线和参与者内聚类的不确定性。不能把同一表上拟合的最优策略频率当作泛化率，不能把 p>0.05 的“未显著高于机会”判成等价。少量 feasibility 参与者主要用于发现明显线索，其样本通常不足以证明线索优势足够小；需要更强结论时先论证测试规模。
